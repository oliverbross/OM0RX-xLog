### FA-001 — High: retained restore confuses remote authority

**Trigger and mechanism.** The retained [restore sheet](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogApp/SettingsView.swift:455) permits unchecking “Restore station and service settings” and explicitly retains credentials. Its button calls `restorePendingBackup` without an authority comparison. [AppModel](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogApp/AppModel.swift:1098) makes a verified pre-restore backup, closes the current database, installs backup A, and preserves current destination B's settings when that option is false (`1135–1151`). It then calls `configureTimers`; [automatic sync](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogApp/AppModel.swift:1633) resumes when B's retained `automaticSync` is true. [synchronize](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogApp/AppModel.swift:925) supplies B's URL/station/token to a `SyncEngine` using A's restored database.

`BackupManager.installDatabase` calls [disableOnlineLogDeliveryAfterRestore](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogCore/LogbookDatabase.swift:543), but that clears separate third-party online-delivery enrollment/candidates. It does not detach Wavelog IDs or bind them to their original server/station. `SyncEngine`'s default `validateRun` is empty; cancellation and database-run locking do not establish destination identity. Its validated complete history proceeds to [merge](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogCore/SyncEngine.swift:406) and deletion reconciliation. [mergeRemoteEffect](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogCore/LogbookDatabase.swift:3163) matches a clean restored row by numeric `wavelogID`; the same ID in B can overwrite A's different contact. An ID absent from B's complete history can instead be tombstoned at [reconcileRemoteDeletionStep](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogCore/LogbookDatabase.swift:3320).

**Independent evidence.** An offline probe uses actual `BackupManager`/database core objects: backup A contains clean `K1BACKUP`, linked ID 42; current B has a different URL/station and automatic sync enabled. Actual close/install/reopen retains A's clean ID 42. Passing a synthetic B contact `W9DESTB` with ID 42 to the real merge changes the same local contact from `K1BACKUP` to `W9DESTB`, leaving one row. The pre-restore recovery still contains `W9BEFORE`. [Raw proof](/Users/oliver/Documents/Projects/OM0RX-xLog/docs/reviews/final-code-audit-2026-10-29/agents/persistence/restore-probe-run.log.gz), [compile/source receipt](/Users/oliver/Documents/Projects/OM0RX-xLog/docs/reviews/final-code-audit-2026-10-29/agents/persistence/restore-probe-receipt.json). No timer, GUI, token or network was exercised; automatic reachability is established by the source call chain.

**Safeguards challenged.** Dirty-contact conflicts, complete-history checks, run locks and recovery backups remain effective but do not prevent authority confusion for clean linked rows. The modern worker explicitly [rejects this mismatched keep-settings restore](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogPrototypeSupport/LiveLogbookMethods.swift:1477) before replacement; the retained UI does not invoke that guard. `AutomaticSyncTests:97–123` exercises the modern route only. Both the chosen backup and pre-restore recovery remain available; irreversible loss and observed provider writes are not claimed.

**Phase 5 repair/test direction.** Apply a shared destination/consent contract to every restore caller. Reject a mismatched keep-settings restore before replacement, or require an explicit reviewed migration with defined linked-ID treatment and fresh sync consent. Do not silently clear IDs and re-upload the log. Add caller-level restore tests with overlapping and absent remote IDs, automatic sync enabled, and matching-destination controls.

## Test gaps and maintainability concerns

The highest-value missing regressions are the actual counterexamples FA-001 through FA-007. In addition, retain explicit tests for startup installation ordering, TCI no-op versus new observation, and failed-retirement recovery across worker EOF/ordinary Quit. These gaps cannot be closed by adding more happy-path fixture combinations with the same preconditions.

Several architectural boundaries make narrow tests misleading:

1. **Duplicated application orchestration.** Retained SwiftUI and worker routes share core data services but have different restore/consent safeguards. Share authority validation at the owning boundary and test both callers; a broad refactor is not required to repair FA-001.
2. **Acknowledged metadata beside editable local data.** A form can render a local draft with base-only time intent. That split needs an explicit effective-intent contract and transition tests, rather than another form-local timestamp workaround.
3. **Per-slot telemetry without explicit active authority.** Source isolation alone cannot infer which slot should supply a single draft. Active selection should be a first-class generation-bound input.
4. **Lifecycle success types omit station uncertainty.** A `Void` registry retirement plus suppressed owner error lets an otherwise structured worker outcome report false cleanliness. Preserve the existing release obligation and expose its result; do not add a second disconnected boolean safeguard.
5. **Parallel method allowlists drift.** Frontend detached reads and native role permissions disagree. Contract tests should compare actual allowed editor methods and negative roles without granting all main-window access.
6. **Scoring context has two representations.** Country facts are durably present yet absent from a recomputation input. Define one authoritative replay/rebuild source; touched-row restoration is insufficient across pages.
7. **Acceptance labels exceed their assertions.** FA-007 and fake-worker-only tests demonstrate why completion bits/component calls do not prove cross-boundary rejection. The narrow frontend bundle headroom also makes clean-lock builds necessary after any related repair.

No additional race, deadlock, permanent memory leak or exploitable security issue was established beyond the concrete findings and unverified concerns above. This statement is bounded by the source/test depth and absence of a new sanitizer/resource/physical run, rather than a claim that those defect classes are absent.
