### FA-010 — High: configuration persistence can prevent fldigi Stop

**Mechanism and caller.** After an admitted `fldigi_send` has completed, make its settings parent unavailable, unwritable or otherwise unable to complete an atomic save. [Explicit Stop](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogPrototypeSupport/LiveFldigiBridge.swift:204) retires receive context/generation, then calls throwing `save(next)` at 208 **before** `returnToReceive(emergency: true)` at 209. [Save](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogPrototypeSupport/LiveFldigiBridge.swift:364) creates the directory, writes JSON and changes permissions. Any error skips `main.rx` at 316. A completed send has no outstanding catch block that will subsequently release it. Repeating Stop encounters the same storage error.

The configuration is cached after successful send; the trigger is a subsequent **write failure**, not merely corrupting the on-disk JSON. Renaming the private settings parent and replacing its old path with a regular file would deterministically inject this boundary without relying on permissions. [Worker routing](/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogPrototypeSupport/LiveWorker.swift:776) and the [visible Stop](/Users/oliver/Documents/Projects/OM0RX-xLog/prototype/src/contesting/Not1MMContestWorkspace.tsx:3797) reach this handler and add no RX fallback. The provider documents `main.rx` as the receive operation; this audit proves its omission from the software path, not delivery or radio state. [Official fldigi API](https://sourceforge.net/p/fldigi/wiki/api_for_xmlrpc_socket_services/)

**Safeguards and origin.** External-I/O denial still applies; automatic lifecycle cleanup still requires owned duty; pending sends retain their final release; a configured `rxAfter` can independently request receive. `rxAfter=false` is valid, so that is not universal protection. Other lifecycle cleanup may still issue RX. Save-before-RX existed at the original remediation baseline. CR-003's unowned automatic-RX root is repaired, but the later description of explicit Stop as unconditional is incorrect.

**Evidence / test gap.** Source call chain confirmed independently. Existing `LiveFldigiBridgeTests` explicit emergency and failed-RX retry cases use healthy temporary storage. The fresh cached fldigi suite passes those 15 cases; none tests this boundary. No new runtime fault-injection proof was executed.

**Phase 5:** attempt the authorized in-memory stop/release independently of persistence, retain release duty until confirmation, and report storage and release failures separately. Add a completed-send, deterministic save-failure regression and verify the RX attempt without weakening profile denial or ownership rules for automatic cleanup.
