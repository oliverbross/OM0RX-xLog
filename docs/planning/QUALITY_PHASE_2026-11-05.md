**Execution plan • 5 November 2026, Darwin • owner: Oliver / OM0RX**  
**Decision:** pause new operator features for one quality cycle. Retain the installed application while measuring it. Advance when evidence supports the common daily workflows on each supported platform, not when a test count reaches a target.

**Continuation checkpoint, 7 November 2026 (Darwin):** the [single current tracker](../audits/quality-2026-11-05/README.md) records completed S25 hosted/ordinary Windows qualification, retained daily-process memory ownership, paging correctness and the separately integrated ADIF boundary correction. The starting evidence and implementation leads below are the original plan, not an instruction to repeat completed fixes or journeys. Candidates remain HELD and quality OPEN. Next: exact corrected-source gates, a newly versioned signed Mac candidate if those gates pass, then one fully attributed foreground desktop memory/idle interval or a retained exact blocker. Installed Mac 1.5.15 bytes and the public release remain unchanged; the user reopened the daily app and its exact installed host/worker pair is process-verified. UTM is started. The retained 1.5.9 application rollback ZIP was rehashed, but the historical pre-1.5.15 data-backup directory is absent; the application archive does not recover that missing backup. The tracker records this distinction without inferring a cause. The provisional budgets below are unchanged; generated 100k and representative ~70k workloads remain distinct.

## 1. What the team is trying to deliver

An operator can install xLog, get through setup with or without station hardware, log and find a QSO on a large log, save equipment settings, and resume after restart on macOS, Windows and Linux. The normal desk should have a measured, bounded memory footprint. Turning off a service or closing its last consumer must stop avoidable work. A busy import, map or awards screen must not starve logging or the control that releases a transmitter.

Feature coverage is strong enough to pause expansion. Country review/recovery, CW, voice libraries, logbook and contest workflows exist. Some device implementations and OS-specific paths remain deliberately limited. Closing this phase means the agreed workflows and budgets have evidence and known gaps have owners; it is not a promise that no defect exists.

## 3. Q01 — diagnose the reported 7 GB first

**Capture the current session before restarting, if still available.** Read-only observation: installed executable path/version, time/uptime, OS build, RAM size, memory pressure/swap, app or specific process name, memory column and units. Record open windows, map/awards/import use, connected cluster/station, skimmer source count, last large operation and whether another build/Codex compiler is running. Capture only app-scoped numeric evidence. Do not change the operator's station, manipulate the live log or collect entire command lines, credentials, database contents or heap dumps in Git.

**Name each memory owner:** UI host, Swift worker, attributable WebContent/renderer/GPU/network processes, Hamlib radio/rotor daemons, contest/Python helpers, and audio/IQ workers if present. Use exact executable/launch identity, process genealogy and runtime ownership where available. WebKit/XPC and shared GPU children may not be PPID descendants: mark unattributable/shared memory separately. Do not charge all WebKit/Edge processes on the system to xLog. Do not equate virtual size with resident memory or sum shared RSS and call it physical memory.

| OS | Preferred primary view | Companion data |
|---|---|---|
| macOS | Activity Monitor memory reading as observed; process physical footprint from supported tools, with ownership. | RSS (separately), memory pressure, compressor/swap, Instruments Allocations/VM Tracker for the affected PID; JS/WebKit snapshots only on a disposable run. |
| Windows | Process tree; private bytes/commit plus private working set, labelled separately. Link WebView2 process groups to the actual host. | Working set, system commit/pressure, ETW/WPR or WebView2 tools for the suspect process. Distinguish trimmed working set from released allocations. |
| Linux | Per-process RSS plus PSS and private dirty/clean from `/proc/<pid>/smaps_rollup` where accessible. | System available memory/swap, web process count and compositor session. Count PSS only once per identified PID; no claim of equivalence to Mac footprint. |

**Reproduction ladder.** Use release builds without DevTools, instrumented/debug builds separately. Keep hardware and fixture fixed for A/B. Start cheap: empty log with no hardware → private copy representative of 69,682 live contacts → synthetic reproducible 100k with realistic metadata. Use a WAL-consistent backup through supported tooling; never copy a live SQLite file alone, use immutable mode on uncheckpointed input or publish production contacts. Keep stable true counts, number of saved views and attachment metadata. Retain private data locally.

1. Record startup/first-run, ready, then 5, 15 and 30 minutes of steady main-desk idle. Distinguish migration, first open, merely process-fresh and controlled disk-cold. Record process/renderer counts, CPU, wakeups, disk/network IO, timer/IPC activity and window state at each sample.
2. Repeat with one change at a time: detached windows; map/cluster; awards with one facet; search; large import preview/cancel; ADIF/POTA export; normal voice desk; then explicitly enabled IQ/skimmer on a fixture. Only measure the relevant connected workloads; state whether a service was enabled but disconnected. Record peak, 1 and 5 minutes after close and after reopening.
3. For a suspect route do 10–20 open/use/close cycles and compare the **settled low-water marks**, retained object counts and process counts. If still growing, one 2-hour run under representative use (longer overnight only when it distinguishes slow growth). Include a normal shutdown check for orphaned helpers. Record profiler-on versus profiler-off to expose observer effects.
4. Use the owner to pick the tool: native worker heap/ARC/SQLite counters; Rust/native host allocation or queue; JS heap, detached nodes/subscriptions and WebView process lifetime; native image/map tile/GPU cache; sample buffers or outstanding snapshots. Separate bounded high-water/reserved memory from live objects and repeated growth. Trace a retaining path or quantify a bounded cache before changing allocation policy.
5. First acceptance: a process-and-operation explanation or explicitly unreproduced incident within a documented envelope. A leak fix must show the previously failing pattern and a stable, useful post-fix result. A high but stable footprint may still warrant lowering; document what uses the bytes and whether an idle operator benefits from it.

### Provisional targets, not measured promises

Calibrate on named representative hardware, OS versions and package profiles **before** choosing pass/fail thresholds. Identify metrics that cannot be aggregated. Initial design goals: normal desk at ~70k contacts with optional services off should aim below **1 GiB** attributable steady memory on the reference Mac; treat a multi-GiB steady idle result as a priority incident until explained. Investigate a repeatable post-warm rise greater than **max(100 MiB, 10% of settled baseline)** over 20 operation cycles or the representative two-hour run, and any repeatable unbounded slope regardless of threshold. A missing WebKit footprint is an incomplete measurement, not a pass.

For idle/no radio, initial goal is **under 1% of one logical core on average** across a ten-minute steady interval on the reference host. Test routine local log save to durable receipt and visible updated row separately; provisional visible p95 target **250 ms** for normal saves on the reference ~70k fixture, with event timestamps rather than screenshot automation duration. Preserve existing enforced worker limits including the two-second held-feed read and signed-worker deadlines. Record native platform baselines separately; approve a justified target change **with evidence**, never by silently relaxing a failing test. Use a representative sample count for percentiles; report all values/min–max for tiny samples. Define separate budgets for intentional active IQ, cluster ingest, import, archive and first migration.

## 4. Q04 — own the background work

Build a small runtime inventory: feature, enablement trigger, owner, active consumers, timer/event/subscription, cadence, max concurrent requests, queue/byte bound, backoff, cancellation, last-subscriber and application-exit behavior. Prefer opt-in trace counters or a support capture that is off by default. Include native timers, async tasks, web renderers, subprocesses, SQLite connections, file handles and network sockets; counting JS timers alone misses most paths.

| State | Behavior to verify |
|---|---|
| Disabled or never configured | No feature-specific network loop, radio scan, audio capture, IQ/DSP allocation or idle helper unless a documented shared owner needs it. |
| Visible view | One owner per stream; multiple panels can share data; bounded snapshots, coalescing and backpressure. |
| Hidden/minimized or last subscriber closed | Pause presentation work, retire read tasks and release scoped caches on their documented budget. A deliberately connected cluster, configured sync or active radio session may continue. |
| Armed/transmitting/recording or cancelling | Existing lease heartbeats, Stop/release supervision, input freshness, reconnect fencing and actual PTT/RX checks remain authoritative even if a panel disappears. UI rendering rate and ownership supervision are separate. |
| Suspend/resume, workspace change, disconnect, exit | Invalidate obsolete callbacks, close handles, remove timers, join or terminate owned helpers, recover state without sending CW or moving a rotor. |

**Source leads, not diagnoses:** `useSharedCW` polls every 750 ms on an unsuspended controller; hiding a document triggers disarm but does not itself remove that interval. Measure unarmed idle before/after; the active holder's heartbeat/expiry must remain correct. The voice desk already suppresses idle polling IPC once settled; an active full snapshot can reload settings and enumerate devices. Measure a lighter progress-only view versus route refresh if it matters. Do not accidentally reintroduce per-window polling: historical work already made several views visibility-aware and bounded main-window hot reads. Scope and count actual background sync (including enabled Wavelog), award rebuilds, spot/cluster classification, map updates, prewarm, audio and IQ. Opening a view for status should not start hardware acquisition.

## 5. Q05 — optimize the database and how results are held

Measure waits in the **whole path**: UI request → queue → lock → SQLite step → row decode/materialization → JSON/IPC bytes → rendering/paint. Use stable query names and redacted bind *shapes*, not real callsigns or literal personalized SQL. Rank queries by total time × frequency, worst interactive delay, rows examined/returned, transient bytes and steady retained bytes. Record database, WAL, write amplification, disk size and time to cancel. Sample SQLite runtime and compile options on the target, connection count, cache/statement/schema memory, FULLSCAN_STEP/SORT/VM_STEP counters as available; inspect `EXPLAIN QUERY PLAN` on representative private or generated data. Avoid parsing version-dependent plan wording as a product API.

Investigate in this order only when the scenario or counters point there:

| Candidate | What to test | Protected property |
|---|---|---|
| Ordinary desk, filter, callsign history and stats | First page vs deep page; sort/filter/selectivity; N+1 calls; duplicate refreshes; index use; small projection before large payload. | Stable ordering including ties, tombstones, revision and draft recovery. The existing small hot-read cache and compact projection are assets. |
| Awards facets | Global award reader appends matching projected rows including extra fields; distinguish full aggregation from the few evidence rows a view needs. Test first/revisit/facet/close. | Worldwide totals, exact QSO drill-down, mixed/unknown policy and snapshot identity. |
| ADIF preview/export | Import preview builds lookup structures over existing live records. Profile preview, cancel/finish, expiry and replacement; a rejected expired token does not alone prove memory reclamation. Examine whole-export snapshots and alternatives: compact identifiers, bounded batches or a private frozen spool. | Duplicate matching, rollback, export field bytes/order and long-lived consistent snapshot. Do not silently undercount or skip unknown fields. |
| POTA export read | Current read constructs `Data` from the whole prepared file's UTF-8 text for each response of at most 12,000 bytes. Benchmark total bytes copied and peak/settled memory. If material, use one bounded immutable byte backing or a private random-access file with deterministic cleanup. | Exact byte offsets, UTF-8 slicing, empty/final chunks, file hash, multi-park semantics. This is an export-specific inefficiency, not proof of a 7 GB idle leak. |
| Cluster/map/reference | Measure full index rebuilds per QSO/reference revision, unnecessary whole entity dictionaries, large temporary sorting and retention after disconnect/close. | Worked/confirmed state, country provenance and ambiguity, map accuracy, update latency. |
| Busy saves and reads | Repeat QSO entry and paging during scans with cancellation; inspect lock waits, long readers/WAL growth and cleanup. Compare reusable views with new indexes or projections using actual workload. | Existing integrity check, durability, stable snapshot, two-second responsiveness guarantee, signed-worker behavior. |

Existing November work already moved blocking cluster reads off the interactive connection and replaced expensive JSON expression indexes with a transactional compact projection. Preserve those gains. A full scan is legitimate for some global totals. No blanket indexes, PRAGMA cache increases, VACUUM, journal-mode changes, weaker durability/integrity, or silent pruning of user data. Apply database migrations only when supported by a reproducible gain; record before/after plans, write cost, disk cost and old-version compatibility. Compare raw authoritative QSO rows, unknown fields, tombstones, settings, receipt history, awards totals, exports and backup/restore on a disposable copy. Verify migration interruption/rollback if schema changes.

## 6. Q02/Q03 — Windows installation and working first-run setup

**Concrete source finding:** The wizard's Hamlib rotor adapter forwards the full worker reply, whose model list is inside `result`. The shared loader expects the already-unwrapped payload and reads `models` on the outer object. A valid result can therefore appear empty and the resolved empty result can persist across Browse attempts. This is a shared first-run frontend path. It explains one credible rotator failure but does not establish which build, driver, provider or step caused Oliver's full report. Radio uses a different station-session adapter.

- The [existing native onboarding acceptance](https://github.com/oliverbross/OM0RX-xLog/blob/da6fefb394944b28be9533ab861be9026306fa8d/prototype/src/onboardingAcceptance.ts#L26-L43) explicitly skips both radio and rotor. Keep that useful offline test and add the two equipment journeys. The worker [reports platform capabilities](https://github.com/oliverbross/OM0RX-xLog/blob/da6fefb394944b28be9533ab861be9026306fa8d/Sources/XLogPrototypeSupport/LiveWorker.swift#L1014-L1027); the current first-run UI intentionally gates direct services. Test the offered Hamlib route on Windows/Linux separately from any decision to port direct providers.
- Reproduce using the real returned shape at the production boundary, not an injected ready-made model array. Verify missing/invalid reply, transient failure followed by success, healthy-cache reuse, independent radio and rotor catalogues, and clear actionable UI. Match or adapt the accompanying patch on current HEAD, then run the attached packaged Windows test case. If already fixed, prove it and do not apply twice.
- Radio: trace provider capability → helper path/manifest → catalogue command/exit/payload → selectable model → validation → save receipt → restart/readback → explicit Connect. Do the same for rotor independently. If radio is saved then rotor fails, retry must preserve fields/confirmed work, avoid a second write and avoid treating partial setup as complete. Wizard Finish configures; it must not transmit, tune, move the antenna or present “connected” merely because settings were saved.
- On Windows test ordinary COM selection, COM10+ handling as supported by the backend, USB absence/in-use, network host:port and missing/refused helper, non-ASCII user path and spaces, unplug/reconnect and offline Skip. Identify exact tested installer/version, Win edition/build, WebView2 version, architecture and account/elevation. Use bundled Hamlib dummy/loopback for automation. A real ordinary non-admin Windows seat + hardware later qualifies drivers/serial access and real readback; TCP mocks or dummy models cannot do that.
- Present native capabilities honestly: separate supported/unconfigured/unavailable, explain why a direct backend is missing and offer the working route. Never advertise a Mac-only backend just to make a Windows screenshot match. Offer Test Connection as a separately deliberate read-only operation where supported, with the precise failing stage and recoverable next action. Never auto-connect solely to finish onboarding.

**Installation policy decision:** Current NSIS packaging explicitly sets `currentUser`, so per-user installation in Local AppData is expected. Recommend a clearly offered **All users / Program Files** installer and a true **Just me / no admin** path. Keep mutable logbooks, settings, voices, caches and logs in appropriate per-user storage or the selected user folder in both modes. Do not move them next to a read-only installed executable. Evaluate Tauri's `both` mode carefully: the documented administrator requirement may defeat the non-admin path; separate signed current-user and per-machine installers sharing the identical audited payload are an acceptable design. Provide accurate option/default text and artifact names. A machine install should need elevation for install/update/uninstall only. Do not run the GUI elevated.

On clean supported native Windows environments qualify interactive default destinations **without a path override**, standard user, UAC approval/cancellation, correctly scoped shortcuts/uninstall/updater entries, WebView2 bootstrap success/unavailable/offline behavior, bundled worker/rotor/radio runtime resources and relative path lookup independent of CWD. Existing silent custom-directory tests remain useful but cannot prove default path or ordinary-user first run. Exercise same-scope upgrades from an actually distributed build plus old per-user → proposed per-machine coexistence/migration (no ambiguous two apps or orphan updater). Protect different users' private data and chosen external WAV folders; uninstall must not silently delete them. Retain matching installer hash, scope, actual executable path, account context, wizard result and restart readback.

## 7. Q06 — parity by operator outcome

At Gate 0 publish supported OS/build/CPU, minimum runtime dependencies, WebView versions, packages and supported backends. Start with the shipping macOS arm64, Windows x64 installer and supported Linux x64 distribution/package from the repository; qualify additional architectures/distros only where claimed. Separate machine-wide install from desktop-user acceptance. Use an ordinary desktop user, no developer toolchain assumed. Test declared Linux package/dependencies on a clean supported distro and relevant Wayland/X11 sessions; test missing dependencies, serial/device permissions and actionable recovery. Keep offline/runtime-only CI plus a small real-session smoke. Browsers and screenshots alone do not exercise native IPC, helper discovery or OS permissions.

| Shared journey | Required evidence on each supported packaged desktop |
|---|---|
| Clean install → first launch → Skip station → log offline | All steps reachable without hardware, visible focus, validation and sensible platform paths; quit/restart preserves setup and synthetic QSO. |
| Configure radio only / rotor only / both | Browse, select, save, restart, reopen settings and explicitly test/connect where supported. Include loss/error/retry; manual model ID is a fallback, not evidence Browse works. |
| Daily logging | Keyboard-only create, edit, search/filter, undo/recovery, sign/date/decimal input, and first/paged view of a large log. Same stored result and field meaning. |
| Import/export/backup | ADIF round trip incl. optional fields and POTA byte checks, non-ASCII paths; backup/restore private fixture; document current external voice asset behavior. |
| Cluster/map/awards/contesting | Spot selection to draft, simulated tune target, worked-before/award evidence, contest entry/serial checks, saved settings and detached window lifecycle. No unintended output or duplicate commits. |
| Station operations | Disarmed/read-only state and explicit connect/disconnect; native success for supported dummy routes; negative outcomes on unsupported routes. Physical radio/rotator/audio acceptance separate. |
| Native UX | Keyboard navigation + visible focus, platform shortcuts, text selection/clipboard, file dialogs, menus, enter/escape in dialogs, screen reader labels, contrast, localization/long strings. Support 1024×768 working area where declared, 100/125/150/200% Windows scaling and representative Retina/Linux scales. Exercise dark/light, resizing, detached window close/reopen, two monitors, displays removed and saved geometry recovery. |
| Shutdown / upgrade | GUI and owned helpers actually terminate; safe cancellation saves expected data, next launch recovers; old candidate/rollback remains usable as documented. |

Classify each cell **PASS (input + outcome) / FAIL / BLOCKED / NOT RUN / documented unsupported**; label simulated vs physical. Screenshots on three OSes show layout, not behavior. macOS normally uses WKWebView, Windows WebView2, Linux WebKitGTK; allow native conventions. Verify equivalent operator outcomes and data. Normal native voice and indexed Direct FLEX CWX currently have Mac-specific capabilities; collect gaps in a separately ranked platform-enablement backlog with an explicit parity decision rather than letting “unsupported” silently cover a broken shared workflow.

## 8. Q07 — defect control and phase exit

Maintain one compact tracker with ID, affected build/platform, exact action, expected/observed behavior, severity, frequency, reproduction data, owner, root-cause evidence, fix SHA, regression and remaining limitations. Example statuses: Reported → Reproduced → Fixed in source → Verified in package → Closed. Never equate green CI with verified physical devices. Link duplicate reports instead of double-counting. Escalate data loss, unintended TX/rotor motion, stuck PTT or unrecoverable startup immediately; broken first-run on a supported route and unexplained sustained multi-GiB normal idle are release blockers for the affected scope. Classify cosmetic or unsupported issues explicitly instead of blocking unrelated platform candidates.

Deliver machine-readable results per profile and OS, including artifact/source hashes, actual OS/UI runtime, data and feature state, measurement method, sample count, before/after medians/p95/peaks/settled values and units, fixture hash, correctness outcome, open defect IDs. Redact private machine/user/callsign/serial/network details from public receipts. Keep measurements comparable; store diagnostic raw logs privately. Add only repeatable, low-noise regression gates to CI. Keep longer GUI/soak runs for candidate qualification rather than every commit.

**Release decision:** (1) rotator regression and the actual Windows first-run journey have evidence, radio disposition explicit; (2) real standard-user and Program Files paths qualified where offered; (3) memory incident fixed with evidence or explicitly remains unresolved — do not advertise it fixed unless reproduced or equivalently attributed; (4) measured high-impact SQL/lifecycle issues corrected without losing data or control guarantees; (5) the common journey matrix and budgets met on each platform claimed ready; (6) no open critical/high release blocker for that claim; (7) reviewed differences, physical devices, signing/notarization and unrun cells listed. Hold only the scope that lacks evidence. Keep 1.5.15 installed, 1.5.9 rollback and source-only CWX intact through development. Producing an acceptance candidate does not itself install it on Oliver's Mac or publish a GitHub Release.
