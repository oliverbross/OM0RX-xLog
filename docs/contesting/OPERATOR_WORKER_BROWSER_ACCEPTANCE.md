# Operator UI to Worker Browser Acceptance

`prototype/scripts/run-contest-operator-browser-acceptance.mjs` is the authoritative test-only acceptance entry point. It compiles the SwiftPM test bundle, launches its selected XCTest in a dedicated POSIX process group, and then runs `prototype/scripts/accept-contest-operator-browser.mjs`. The driver renders the production `ContestWorkspace` in a headless Vite page and drives its actual controls with `agent-browser`. The compiled test host constructs the production `LiveWorker`, `LiveLogbookMethods`, contest lane, and SQLite repository with the test-only Contesting Test profile constructor, then exchanges the same JSON-line request and response frames over child-process pipes. Direct opt-in execution of `ContestOperatorBrowserAcceptanceTests` fails closed unless the outer-runner guard is present; an ordinary filtered test run still discovers the test and skips it.

The gate creates only an empty synthetic workspace under a new private Application Support root. It supplies no station, radio, rotor, CW, audio, PTT, network, or credential adapter. The worker's health response must report the isolated contest profile with all external effects false before the browser opens. Test-only lifecycle frames fully shut down the old worker before reopening the same isolated store; they are recorded separately from ordinary browser requests. Every browser command has a deadline. The outer runner asynchronously drains bounded XCTest output and applies a full-host deadline to the owned process group, escalating TERM to KILL and reaping recorded PIDs. Test-only stalled-response and stalled-shutdown probes prove that the XCTest host and its Node descendant are gone before a later run begins. A separate parent-and-grandchild probe covers a descendant that ignores TERM. The Swift watchdog remains defense in depth; it does not constitute the full-host bound by itself.

The bounded first gate exercises CQ WW CW/SSB in Run and CQ WPX CW/SSB in Search & Pounce, with two contacts per session, missing-exchange `AGN`, authoritative invalid-zone/serial rejection after autosave and owner-idle admission, a same-call/same-band duplicate indication, WPX durable serial allocation, and score assertions derived from the pinned operator oracle. For each invalid draft it arms the operator, attempts Enter, and proves that the simulated-output, reserve, and commit counts remain unchanged. It also covers one clean worker restart/reopen, a CQ WW CW correction and deletion path, and one export per session. The test-only save adapter reads the prepared artifact through `contest_export_read`, verifies its SHA-256 digest, and writes the Cabrillo or ADIF bytes only inside the private acceptance output. It does not yet prove both operating styles for every profile, independently parse export fields, or assert the score after correction and deletion.

Evidence verifies the requested source HEAD against Git, proves the source snapshot stayed unchanged across compilation and execution, and records whether the development run was dirty, the tracked-diff digest, untracked source digests, the compiled `XLogPrototypeTests` bundle executable hash, the separate XCTest runner hash, process-group probe PIDs, UI action ledger, every worker request/response frame, simulated-output trace, screenshots, captured-export hashes, and isolated filesystem inventory. Final acceptance requires a rerun from the reviewed clean commit. A passing result proves a headless development UI and real `LiveWorker` cooperate through the reviewed protocol. It does not prove the packaged worker or app identity, native window or save-dialog behavior, RF or device timing, crash recovery, sponsor submission acceptance, or current contest-date/category eligibility.
