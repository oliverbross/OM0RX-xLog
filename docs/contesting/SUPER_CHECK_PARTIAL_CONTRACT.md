# Offline Super Check Partial foundation

This foundation imports a caller-provided offline `MASTER.SCP` byte sequence into an immutable index. It performs no network access, does not update global reference data, and does not read or modify a contest draft. Packaging and refresh policy are separate work.

The parity reference is the read-only `oliverbross/contest-sw` checkout at `7c8b499225a73f7f8f792246881bd7aefc05452f`, specifically `not1mm/lib/super_check_partial.py`. That implementation searches when the normalized query has at least two characters, ranks with RapidFuzz `QRatio` (normalized Indel similarity), applies a `0.8` penalty when the candidate does not start with the query, keeps scores at least 60, and returns at most 20. Its bundled manual says three starting characters, which conflicts with the executable two-character fuzzy behavior; this foundation follows the executable behavior.

The importer accepts UTF-8, recognizes the current first-line `!!Order,1,1` MASTER.SCP format marker, ignores blank and `#` comment lines, uppercases callsigns, rejects non-ASCII callsign characters, preserves first occurrence order, and records duplicate count. The pinned source accidentally retains the format marker as a candidate; excluding that non-callsign, uppercasing, and strict invalid-line rejection are deliberate hardening differences. Imports are bounded to 16 MiB, 100,000 unique records, and 64 raw bytes per line by default. Raw line length is enforced during incremental byte traversal before copying, UTF-8 decoding, comment handling, or whitespace trimming. Retrieval timestamps must be finite. The index computes SHA-256 over the exact imported bytes. If an expected SHA-256 is supplied it must match; metadata distinguishes a matched expected digest from a digest that was only computed locally.

Search is an asynchronous nonisolated core operation, so Swift runs it on the generic executor rather than a UI actor. It checks cancellation before work and every 256 records. The default budget covers the full maximum 100,000-record catalog. A smaller explicit budget returns `isPartial=true`, the evaluated count, and results that are best only within the deterministic imported prefix. Partial results never claim whole-catalog ranking. Equal scores retain first occurrence order, matching Python's stable score sort.

Queries are limited to 2...32 raw UTF-8 bytes and must be ASCII before trimming and uppercasing, so Unicode case folding cannot turn an unsupported input into a plausible callsign. Every result carries the exact session, workspace generation, and request identity supplied by its caller. Selection is a separate operation that requires all three values to match, requires the complete dataset metadata to match this index, resolves the digest-and-ordinal identity through the immutable index, checks that the result's candidate text equals the stored record, and returns the authoritative stored callsign. The engine never selects automatically and never provides or changes an exchange.

The focused score fixture is independently generated with RapidFuzz from the pinned behavior. The 100,000-record test proves full bounded evaluation and deterministic output; it is not a wall-clock performance claim. Runtime benchmark evidence should be recorded separately on representative release hardware before setting a UI latency claim.
