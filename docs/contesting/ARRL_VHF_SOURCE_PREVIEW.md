The original three identities preserve the source's per-band duplicate policy, four-character Maidenhead grid exchange, grid multiplier per band, and season-specific point table. Their canonical bytes and replay behavior stay unchanged. Separate `-fixed-official-grid-preview` and `-rover-official-grid-preview` identities use version `2.0.0-official-grid-preview`; they make station category explicit rather than inferring rover operation from a `/R` callsign.

The official-grid previews use a four-coordinate duplicate key: contacted callsign, band, transmitting station grid, and contacted station grid. Mode is deliberately absent. This admits a fixed station working the same rover from multiple rover grids, an own rover working the same fixed station from multiple activated grids, and rover-to-rover contacts for distinct grid pairs. Rover previews also add one global multiplier for every transmitting grid from which at least one valid contact was completed; contacted grids remain per-band multipliers. Correction and deletion rescoring therefore promotes the earliest remaining contact for the affected four-coordinate key and recalculates both grid sets from the coherent contact collection.

That correction is pinned to [ARRL Jan/Jun/Sep VHF Rules 1.2](https://www.arrl.org/files/file/Contest%20Rules%20PDFs/2024/Jan-Jun-Sep%20VHF%20Contest%20Rules%20-%201_2.pdf): clauses 2.2 and 2.2.1 define band/grid contact eligibility, 5.3.1 counts received grid fields per band, and 5.4.2 adds each grid activated by a rover. The implementation does not infer category from callsign text.

The official-grid identities also model the directional eligibility in rule 2.3. ARRL's [current September VHF contest page](https://www.arrl.org/september-vhf) explicitly groups the United States, Canada, KH0-9, KL7, KP1-5, CY0, and CY9 as W/VE: a station in that group may contact any resolved entity, while another DX station may contact only a W/VE station. The finite ADIF entity set is materialized from bundled `cty.csv` SHA-256 `e5d907fb16842cfa3dd8502c20ebe6bfc2039c6f5b2cc73f9ea6d3f5915f6d6d` and becomes part of each new definition digest. Admission uses the immutable station and contacted `ContestEntitySnapshot` values; it never infers eligibility from a callsign prefix. This pins the current bundled resolver edition. Deleted or future entities require a new reviewed definition identity rather than changing an existing session silently.

The same official page defines Cabrillo mode classes as CW, PH for SSB phone, FM, and DG for digital modes. The official-grid preview therefore preserves each actual app and ADIF mode (`CW`, `SSB`, `AM`, `FM`, `RTTY`, `FT8`, `FT4`, or `MSK144`) and maps only its Cabrillo class: CW→CW, SSB/AM→PH, FM→FM, and the four admitted digital modes→DG. This is a finite reviewed preview rather than an assertion that those four digital modes exhaust every legal emission. These definitions deliberately have no operator policy, so admitting a typed log mode does not claim an RF, audio, CW, or digital-output adapter.

January assigns 1/1/2/2/4/4 points across 6 m through 23 cm and 8 points on every represented band at 2.3 GHz and above. June and September assign 1/1/2/2/3/3 and then 4 points on every represented high band. The portable contest band plan mirrors the pinned comparator through 1 mm plus its submillimeter bucket. The independent all-band fixtures therefore expect 102 points × 17 multipliers = 1,734 for January and 56 × 17 = 952 for June and September.

There is one explicit correction relative to the pinned executable comparator. Each plugin tests for the literal database band `2300+`, while the shared pinned `get_logged_band` returns individual canonical numeric values such as `2300.0`, `3300.0`, and `10000.0`. The resulting Python path awards zero points at 2.3 GHz and above despite the plugin comments and published rules. The fixture records both executable and corrected tables; the preview deliberately implements the published 8-point January and 4-point June/September branches rather than reproducing that defect.

The source-shaped operator archive preserves the Python field order and its minimum-width frequency behavior: frequency, mode, UTC date/time, station call, sent grid, contacted call, received grid. The reusable export-column extension is optional and encoded only when requested, so existing canonical declarative bytes and digests remain unchanged.
