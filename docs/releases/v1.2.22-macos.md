# OM0RX-xLog 1.2.22 — seamless spot tuning and local radio recovery

Version 1.2.22 removes obsolete renderer-side radio/QSO fences from the normal
spot-selection workflow. The Remote Station Agent remains the authority for
station operations; the local app now retains the newest rapid spot selection
and applies that selection as soon as any in-flight activation settles.

## Source boundary

- Exact packaged source: `6c4dd993fd42f78d030a0e674f830ff339380842`.
- Source branch: `codex/dual-radio-settings`.
- The Active QSO `Follow radio` checkbox and its misleading local-authority
  errors are removed. The separate Band Maps follow feature is unchanged.
- Finished or stale local Read-radio and spot-activation journals reconcile
  automatically instead of blocking later spot selections.
- Rapid spot selections are last-click-wins: no superseded tune is replayed.
- Spot-tune admission depends on the requested target, not the currently
  observed frequency or its regional-band classification. Regression coverage
  starts the observed radio at 7.236 MHz with band `Other` and admits the new
  target.
- Direct Agent tuning accepts both the atomic `tune_simplex` capability and the
  legacy compatible pair `set_frequency_hz` plus `set_mode`.
- Settings > Radio 1/Radio 2 includes `Refresh local radio state`. It clears
  only xLog's local draft/receipt/observation state and refreshes the passive
  station snapshot; it does not disconnect the Remote Station Agent, rotor, or
  Wavelog.

`Connected` at 7.022200 MHz CW, the rotor as `ROTOR CONNECTED`, ShackCQ as

not click a live cluster spot, command physical rotor motion, transmit, or run a
live Wavelog synchronization; those actions require operator observation of the
remote station and are not inferred from local UI state.
