# Integration alpha.26 — saved Agent startup resume and shared Sync ownership

Alpha.26 is a focused hotfix on top of alpha.25. It restores the selected saved
Remote Station Agent once during native application startup instead of leaving
the station session stopped until the operator clicks **Connect saved Agent**.

Alpha.26 also carries the next DATA-10 ADX validation slice and generation-bound,
receipt-backed Sync mutation ownership shared by the main and independent
Settings surfaces.

## Station control and ownership boundary

- Exact packaged source: pending final clean-source freeze.
- Startup may resume only the selected `direct_agent` provider with a non-empty
  saved endpoint.
- Full CAT and amplifier controls are enabled by default so the operator can test
  Tune, PTT, CW and amplifier actions without reconnecting or clearing an
  artificial receive-only gate. The setup retains an explicit opt-out.
- The generated startup request only connects the saved Agent. It does not Tune,
  key PTT/CW, switch the amplifier, change frequency/mode or move the rotor.
- The token is omitted from the request so the existing Swift endpoint retrieves
  it from macOS Keychain for that saved endpoint.
- Explicit disconnect/forget intent, a provider handover, a newer selection or
  control revision, and any pending/unknown Station Control receipt all prevent
  automatic resume.
- Admission uses the existing durable Station Control journal before transport;
  lost startup acknowledgement remains inspectable and is never replayed.

Focused validation passes **10 startup-filter** and **44 Agent setup/control UI**
tests plus TypeScript. Shared Sync ownership passes **31 Swift**, **34 frontend**
and **14 distinct native Sync/monitor** tests. DATA-10's transfer suite passes
**469/469** tests plus TypeScript. These tests do not contact the live station.
