# OM0RX-xLog 1.4.5 Beta 1

A faster operator desk, a guided first launch, and native installers for macOS, Windows and Linux.

## Faster logging and window changes

This beta reduces the work between saving a contact and seeing the updated logbook. Callsign history queries seek indexed exact and portable calls, and return only the fields needed by the display. Statistics and award caches follow the actual QSO revision, so unrelated settings, drafts and background service writes do not rebuild them. Transaction rollback also retires provisional cached results.

The first logbook rows can paint before the rest of a page arrives. A bounded cache retains recent rows and local panel snapshots across navigation; optional idle warming is limited to one small batch per minute per workspace. Contact changes retire the cache. Hidden Chaser, weather, Spot History status and HF panels pause their periodic work.

First-page reads now complete before statistics and optional catalogue warming begin. Previously displayed rows stay visible, marked as updating, while a replacement page is fetched. Award-catalogue queries start with indexed candidate contacts and read a compact projection, reducing the work that can hold up a later logbook request.

Statistics and award calculations now use bounded background readers with their own read-only SQLite snapshots. A running calculation no longer occupies the foreground logbook queue. Saves retire obsolete calculations; workspace replacement cancels and drains them before replacing files. Revision and workspace-generation checks prevent an older result from appearing in the current workspace.

Automatic workspace updates preserve the operator’s current window and minimized windows. Reopening Main takes priority over an older presentation request. Explicit window and layout commands still reveal the requested tools. Data-only refreshes reuse the current presentation instead of repeatedly presenting the desktop.

Large-log startup still performs a full database integrity check before opening the workspace. This initial check can take time; warm navigation and save responsiveness are qualified separately from that first-open verification.

Contesting’s process readers now use dedicated I/O threads, keeping idle pipes off Swift’s shared executor. A private multi-host regression reproduces the old stall and verifies the corrected path without removing protocol bounds or backpressure.

## Station setup and everyday operation

- First launch guides a new operator through station identity, optional radio and rotator configuration, and integrated-only or Wavelog-connected logging. Radio and rotator steps can be skipped. Choices are saved; existing profiles keep their settings. Connections and synchronization start explicitly from Settings.
- Auto rotor retains the operator’s enabled preference across temporary interruptions and shows when it is paused. Stop, manual movement and uncertain hardware state still require the appropriate explicit resume.
- About OM0RX-xLog has a larger icon and Oliver Bross’s contact details.
- CW Decode is hidden by default. It remains available as an **unfinished Alpha** option in Settings, where its menu link can be enabled.
- KPA500 and remote station details appear only when using the Remote Station Agent.
- Settings is available through the application menu on macOS and **Edit → Settings** on Windows and Linux, with the usual Command/Control-comma shortcut.
- Windows backup staging handles long Unicode paths while retaining file-type checks, package seals, size limits and cleanup checks.
- Recorder archives, CW-entry journals and recorded voice profiles use native durable publication on Windows as well as Unix. File data is flushed before publication; new media cannot overwrite another recording. Windows recorder storage checks use actual available space and retain the selected directory identity, so replacing that directory stops further writes.
- Windows recorder media status verifies content afresh for each response. Overlapping logbook or bookmark rows share that verification within the response, avoiding repeated reads of the same recording. Playback and export retain their independent integrity checks.
- Windows includes a private Python contest runtime. Linux declares its Python dependency. Packaged-runtime checks create, save, reopen and remove a synthetic contest through the shipping bridge.

Wavelog uses the same API v2 client and synchronization engine on all three desktop systems. Windows and Linux now also expose Wavelog reference-catalogue status, refresh and scheduling, with the same credential scoping, redirect protection and workspace cancellation rules. The operating system hosting the Wavelog web application is independent of the xLog desktop platform.

This beta also includes the earlier portable-station country correction, prompt save acknowledgement, foreground-window fixes, rapid QSY/rotor cancellation handling, Maestro spot-delivery repairs and Billy NZ3C’s Ham Mission Control integration under **Window → HM Control**.

## Install

| System | Download | Installation |
| --- | --- | --- |
| Apple Silicon Mac, macOS 14 or later | `OM0RX-xLog-1.4.5-Beta-macOS-arm64.dmg` | Open the disk image and drag OM0RX-xLog to Applications. |
| Windows 11 x64 | `OM0RX-xLog-1.4.5-windows-x86_64-setup.exe` | Run the per-user EXE installer. Installing Microsoft WebView2 requires internet if that runtime is absent. |
| Ubuntu 24.04 amd64 | `OM0RX-xLog-1.4.5-Beta-Linux-x64.deb` | Install with `sudo apt install ./OM0RX-xLog-1.4.5-Beta-Linux-x64.deb`. |

Linux also has a relocatable runtime archive. No Swift, Node or Rust development tools are needed to run a packaged application. Linux credential storage requires a working desktop Secret Service, such as GNOME Keyring; local-only logging can be used without saved service credentials. Windows uses Credential Manager and macOS uses Keychain. Platform-specific station providers have different availability; Hamlib radio/rotator helpers and shared local/Wavelog services are included on all three systems.

## Data and beta boundaries

The installers contain application resources only. They contain no developer logbook, operator profile, account settings or credentials. Payloads are audited against inventories; public checksums and provenance accompany the release. Existing user data is stored separately from the installation.

macOS distribution is Developer ID signed, notarized and stapled. Windows is an unsigned beta; its checksum verifies download integrity. Native CI acceptance on Windows Server 2022 and Ubuntu 24.04 does not establish compatibility with every Windows desktop, Linux distribution or connected radio. Physical rotor, amplifier, transmit and account-provider qualification remains separate from fixture testing. CW Decode remains unfinished.
