# DXpedition Map parity ledger

This feature is an independent native tool window. It does not replace World Map, Band Maps, Cluster, or Chaser & DX, and it does not create another cluster or radio connection.

| Requirement | Implementation | Evidence boundary |
|---|---|---|
| Current/upcoming DXpedition catalogue | Shared opportunity owner reconciles overlapping exact published aliases from ADXO/425DXN, preserves separate visits and conflicting explicit IOTA groups, and retains recently ended records for 48 hours. | Parser/projection regressions and opt-in primary-provider check; availability remains time-specific. |
| Multiple calls for one operation | Exact published aliases, including portable calls explicitly introduced by `as` in ADXO information, join one occurrence. Prefix-only announcements remain visible but have no draft-load authority. | Senegal/Honduras regressions and similar-prefix tests; no broad prefix admission. |
| Independent cluster view | DX Map reads the bounded `contest_spots` projection before ordinary Cluster presentation filters. | Native identity tests prove visible and pre-filter rows share the same retained activation identity. |
| Live/Active/Recent/Upcoming | Derived from cluster observation age and UTC operation dates: `<45m`, `<6h`, `<48h`, or future start. | Boundary model tests; schedule/fetch time is never a live observation. |
| Passive navigation | Card and marker clicks only select details. | Component test proves no activation from card/pin. |
| Tune & load | Explicit frequency-row action uses the existing native spot-activation transaction and exact integer Hz. | UI/native tests; physical radio acceptance remains separate. |
| Callsign-only load | An upcoming operation with no observation uses the existing opportunity draft-only action. | Component and native retained-feed tests; no frequency is fabricated. |
| Selected receiver | Uses the shared station selection/telemetry owner for Flex LAN, Remote Agent, Hamlib, and Direct TCI. | Native admission tests; no DXMap-specific controller. |
| QSO history | Existing opportunity history fields are displayed when available. | Local projection only; this surface does not write a QSO. |
| Club Log totals/last QSO | Primary public `expeditions.php?api=1` supplies exact totals and UTC last-QSO times, joined only to the dated occurrence; source freshness remains visible. | Tuple/schema/future-date regressions and live S9R comparison. QSO/h and watchers remain unavailable, as on the reference. |
| Geographic coverage and markers | Published/reference positions take priority, then the declared DXCC entity/CTY approximate centre. Callsign/status/frequency labels remain visible at world zoom; upcoming markers use dashed borders and overlapping labels retain geographic leader lines. | Actual provider comparison mapped 62/62 returned operations; real Map DOM tests verify labels, occurrence identity and passive selection. |
| Retained activity | Exact-call 48-hour reads use the existing durable Spot History archive, independently of the newest 500 shared cluster rows. Historical evidence never receives a tune token. Club Log's actual last-QSO time also establishes activity age without inventing a frequency. | Archive reopen after 600 unrelated reports; model age boundaries and disabled historical actions. |
| Operating module | Browse in either module; explicit actions are disabled with an explanation while Contesting or a module transition is active. Native Normal Logging admission remains mandatory. | UI module regression and existing native guard. |
| Languages and layout | English/Italian controls, keyboard-native buttons, narrow layout, reduced-motion CSS. | Source/UI review; full assistive-technology and multi-monitor acceptance remains open. |

Remaining external gates: physical-radio runs, long-session profiling and exact packaged candidate acceptance. No rate/watcher metric is fabricated. Approximate entity centres do not claim an expedition's exact station location.
