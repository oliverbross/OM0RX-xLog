## Constrained smoke harness

[hamlib-dummy-smoke.mjs](../prototype/scripts/hamlib-dummy-smoke.mjs) uses only Node standard modules. It accepts exactly two executable paths in radio/rotor order, checks both report Hamlib 4.7.2 and validates their roles before launching anything. It does not accept model IDs, serial devices, endpoints, ports or arbitrary daemon options.

Each spawned helper receives only `-m 1 -T 127.0.0.1 -t <ephemeral-port>`. Ports are selected through an exclusive loopback reservation and released immediately before spawn; startup/bind failure aborts rather than falling back to another endpoint. Because Hamlib opens its own socket, reservation release/spawn has a brief ordinary bind race; the harness checks child health/bind failure and dummy identity before sending writes. This is a constrained lab launcher, not the final production ownership supervisor.

The harness bounds version execution (3 seconds), startup (4 seconds per child), command responses (2 seconds, 8 KiB), rotor target observation (4 seconds plus any in-flight bounded response) and shutdown (1-second TERM grace then 1-second KILL grace). It handles split/coalesced TCP lines, serializes requests, rejects unexpected replies, emits JSON pass/fail evidence and exits nonzero for failure. Its temporary working directory is removed. Only its own children are stopped; their exit and released ports are verified even on interruption/failure.

Allowed protocol commands are hardcoded: dummy identity `_`, frequency set/read `F`/`f`, mode set/read `M`/`m`, and rotor position set/read `P`/`p`. No PTT, tune, CW, accessory, station or physical-device command exists in this harness. Frequency is 14,074,000 Hz and radio mode USB/2400 Hz; rotor target is azimuth 12°, elevation 6°.

  /tmp/om0rx-hamlib-4.7.2-p1.kEfsHE/hamlib-4.7.2/tests/rotctld

Final successful children were PIDs 41356 and 41357 on loopback ports 64583 and 64584. Both stopped; the radio exited 0 and the rotor exited on SIGTERM. The harness then successfully rebound and released each exact port (`portReleased: true`).

The first draft used an immediate rotor readback assertion for 123°/20° and failed after 7 successful checks because its first observation was 0°/0°. Both children still stopped. Inspection of pinned `rigs/dummy/rot_dummy.c` confirmed model 1 simulates movement at 6 degrees/second. The corrected harness selects a small target, polls bounded observed movement and distinguishes successful command acknowledgment from arrival. Two subsequent complete runs passed; the final run includes role and released-port verification.

Additional executed harness checks:

- `node --check`: passed, exit 0.
- Existing Homebrew 4.6.5 helpers: rejected with exit 1 and zero launched helpers (expected negative case).
- Missing arguments: rejected with exit 1 and zero launched helpers (expected negative case).
- Reversed 4.7.2 helper roles: rejected with exit 1 and zero launched helpers (expected negative case).
- SIGTERM sent to the harness after 1 second during simulated rotor motion: JSON `FAIL`, error `Interrupted`, exit 1 (expected); both owned children stopped and both ports were verified released. Seven protocol checks completed before interruption; arrival was not marked passed.

Protocol timeout/oversize branches are implemented but have not yet been exercised with a fault-injection server. No fixture count is invented for them. These direct integration/negative runs are not a separate Node unit-test suite.
