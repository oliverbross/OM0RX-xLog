## NEW-FE-001 — ADX export emits deprecated names as unsupported 3.1.7 record elements

- **Severity: Medium** — an ordinary export of retained older fields produces XML outside its declared ADX 3.1.7 vocabulary. Consumers enforcing that vocabulary can reject the exported file. Original local contacts remain intact; ADI without extension sidecars is an available fallback. This is an interoperability defect, not evidence of database corruption.
- **Confidence: High. Verification: supported by exact source/primary-schema comparison and reproduced with bounded independent structural validation.** Exact validation with the unmodified official XSD is blocked by an unrelated upstream schema regular-expression issue, explicitly recorded below.
- **Locations:** `/Users/oliver/Documents/Projects/OM0RX-xLog/prototype/src/live/adifTransfer.ts:93` and `:106` list `GUEST_OP` / `VE_PROV` in `standardADXFields`; `:148` / `:151` treat them as ASCII strings. `ADIFExportDocument.append` at `:354` emits them as native record elements; `finish` at `:393` declares ADIF version `3.1.7`. Native preservation path: `/Users/oliver/Documents/Projects/OM0RX-xLog/Sources/XLogCore/QSOADIF.swift:116`, `:147` and `:186` retain imported `extraFields` through ADIF export; neither field is normalized or removed there.
- **Trigger:** import or retain a QSO with a legacy `GUEST_OP` or `VE_PROV` ADI field, then choose ADX export. The writer emits `<GUEST_OP>W1AW</GUEST_OP>` or `<VE_PROV>ON</VE_PROV>` inside `<RECORD>` under a 3.1.7 header.
- **Mechanism and primary evidence:** the [official ADX 3.1.7 XSD](https://adif.org/317/adx317.xsd), retrieved in this pass, contains 179 allowed standard record names; this implementation lists 181. Exact difference: `GUEST_OP`, `VE_PROV`; no other missing or extra names were found by `schema_check.py`. The schema identifies itself as `3.1.7.0` and describes export-specific support excluding deprecated features. Retrieved bytes are retained as `adx317.xsd`, SHA-256 `ce7a86832f7be4a232d2c1ae7432925feb2be8506cba24345b7e3ad994a87331`.
- **Reproduction:** `codec-verification.test.ts` runs the actual `ADIFExportDocument` and creates `NAME.adx` (control), `GUEST_OP.adx`, `VE_PROV.adx`; all three roundtrip through the app's own decoder, showing why mirrored tests do not detect the vocabulary mismatch. `validate_schema_structure.py` compares exact official record element declarations, then validates with a derived schema described below. `NAME` passes; both legacy fields fail as unexpected elements. See `codec-schema-structural-validation.log` and `schema-structural-results.json`.
- **Validation limitation:** direct `/usr/bin/xmllint --schema adx317.xsd` cannot compile an unrelated New Zealand subdivision pattern containing `(?=...)`; even the NAME control fails at schema compilation, exit 5. Those original results are preserved in `codec-schema-validation.log`. For the bounded follow-up, `adx317.unused-nz-facet-relaxed.xsd` removes exactly this one unused pattern facet, with no record-element declarations changed. None of the test files contains that subdivision field. This is not reported as an unqualified full-XSD validation pass. Exact element-name comparison against the original unmodified primary schema independently establishes the unsupported vocabulary.
- **Safeguards / false-positive challenge:** the default ADI path preserves these fields and does not make the claim of valid ADX vocabulary. Native `QSO.adifRecord` canonicalizes deprecated MODE values but does not canonicalize these field names. Existing tests enumerate `GUEST_OP` and `VE_PROV` as supported strings, validating against the app's own assumptions rather than the independent export schema. The explicit allowance for generic/uniform namespaces does not add record element names to the schema.
- **Focused fix:** distinguish import-only preserved field names from the export vocabulary. Either use a reviewed lossless USERDEF representation with an explicit declaration or stop ADX export with an actionable ADI fallback message; do not emit unsupported standard elements or silently drop the values. If canonicalizing to modern fields, resolve collisions and preserve original provenance deliberately.
- **Regression:** validate actual frozen native export frames containing each name against an independent pinned vocabulary/schema; include the valid NAME control, a standard-field collision, mixed legacy/current records, ADI exact preservation, and app import/export roundtrip. Do not merely extend the same frontend allowlist used by both encoder and decoder.

Historical-contact editing uses `isEditing=true` and is a different control case, so tests for historical edit preservation do not invalidate CR-008.
