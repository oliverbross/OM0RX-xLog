## Confirmed current finding

### P2 / Medium — A later replica rebuild loses imported contacts' country context, changes scores and blocks subsequent catch-up

**Trigger:** On a configured authority/client pair, import a valid WPX historical contact whose callsign was not already resolved in the client's reference map, synchronize it, then import and synchronize a second such contact. This reflects the production native contract: `PythonContestLane.swift:439–470` creates the initial per-call reference with the entrant station and hydrates each historical import's CALL. Replica change requests do not receive comparable per-call enrichment there.

**Call chain and exact mechanism:** `adif_import.py:40–45,123–132` pins the newly resolved country on the authority and includes it in the durable imported identity. `host.py:2189–2204` now correctly publishes that import as a wire `commit` with its identity. `Host.apply_replica` persists `afterIdentity.country` to `xlog_qso_identity` at `host.py:2435–2439`, but does not make that country available to the replica's scoring context. Its rebuild at `host.py:2537` calls `rebuild` (`4626–4725`); `cty_lookup` (`689–691`) reads only `state.reference.countries`. The pinned WPX points callback (`python/vendor/not1mm/upstream/not1mm/plugins/cq_wpx_cw.py:157–199`) returns zero when that callsign has no reference entry. Only rows in the current page's `touched` set are restored to the authority's images (`host.py:2538–2544`). An earlier import outside the next page is therefore silently changed to zero points. The next genuine master correction's before-image cannot match, so `host.py:2412–2417` rejects catch-up with `replica_conflict`.

**Actual-source evidence:** `probe_import_country_replica.py` uses the unchanged actual Host and configured independent roots from `ImportedReplicaTests`. It first proves exact row/identity equality for enriched import `K9XYZ`. After the separately synchronized import `K8XYZ`, the first row has master Points=3 and replica Points=0; total scores are 12 and 6 respectively. The replica still durably holds the correct country in its identity table, but not in its scoring reference. A real master `qso_correct` then fails replica catch-up with `replica_conflict`. Reopening both Hosts preserves that divergence. Raw proof: `import-country-replica.log`.

**Safeguards and impact boundary:** Contacts and country identity remain retained; the correction page rolls back rather than overwriting mismatched history. No contact deletion, audio loss, physical transmission or sponsor acceptance is claimed. The error is incorrect replica scoring and a subsequently blocked supported replication stream.

**Origin:** The country-context omission and rebuild behavior predate these repairs. The CR-004 repair exposes this path for newly supported import replication; therefore this is an adjacent current defect in the repaired contract, not evidence that the wire-kind/identity repair itself is absent. The original specific `adif_import` wire-kind failure is fixed.

**Test gap:** `test_remediation_import_replica.py` uses `K1ABC`, already included in both peers' initial fixture reference. It compares the touched imported row and then corrects/deletes the same row; that avoids rebuilding a previously imported, untouched row without its country context. Add a native-shaped station-only initial reference, per-import country enrichment, two separately paginated imports, score comparison, later correction and restart. The expected scores should come from the independently retained country facts and pinned WPX rule, rather than comparing only the newly touched row.

## Rejected lead and migration control

The independent WAE probe initially showed a legacy bound client cannot run Recalculate after its authority adopts 1.0.1: catch-up returns authority_mismatch and local Recalculate returns replica_read_only. This is explicitly documented in `docs/contesting/WAE_NUMERICAL_AREA_REMEDIATION_2026-10-29.md`: preserve the old replica and establish a fresh matching client and baseline. The same actual-source probe then creates a fresh independent matching client with a new session/workspace UUID, successfully baselines all 3 contacts at score 6, and proves the old replica's 3 contacts remain. This is a documented operational migration limit, **not a confirmed defect**. `wae-replica-upgrade.log` retains both the failing old-peer control and passing documented migration control.

Other rejected leads: fresh shared serial races are covered by SQLite's immediate writer transaction and uniqueness constraint; import/remote events do not inherit local recorder attribution; legacy missing identity returns a bounded replication error without modifying source history; malformed/partial ADIF refuses the whole import; closed DB errors propagate; export scope is frozen independently of display pagination. Unix rename-then-directory-sync can fail after publication, but the owner retains the transition fence and requires restart; that preexisting fail-closed policy is not counted as a new regression.

## Bounded follow-up: retained restore authority

### P1 / High — Retaining current Wavelog settings when restoring another destination's backup reuses foreign remote IDs and resumes automatic synchronization

**Supported trigger:** The retained SwiftUI restore sheet explicitly offers `Restore station and service settings` (`Sources/XLogApp/SettingsView.swift:455–478`). Uncheck it while restoring a valid backup from destination A into a current destination B configuration with automatic synchronization enabled and B's already configured token. A and B may be distinct servers or station profiles, each legitimately using remote contact ID 42.

**Current call chain:** `AppModel.restorePendingBackup` (`1098–1170`) captures the keep-settings choice at 1105, preserves a recovery backup, closes the current DB and installs A's database at 1135–1140. Because restoreSettings is false, `1148–1151` preserves B's service settings; the UI also expressly says credentials are unchanged (`SettingsView.swift:465`). No destination comparison or remote-ID detachment occurs. `BackupManager.installDatabase:329–335` calls `disableOnlineLogDeliveryAfterRestore`, but that method (`LogbookDatabase.swift:543–550`) clears only separate third-party upload enrollment/candidates. It does **not** remove the restored Wavelog IDs, dirty/baseline state or modify the retained AppModel settings.

The restore calls `configureTimers` at 1157 (also on its error path at 1166). That method (`1633–1652`) restarts a timer when B's retained settings.automaticSync is true. `synchronize:925–936` constructs a SyncEngine using the retained B URL, station ID and token against A's restored database, with no destination/restore-consent validator. A successful B history then reaches `SyncEngine:406–409` / `LogbookDatabase.mergeRemoteEffect:3163–3174`: a clean restored A contact is matched by its foreign numeric wavelogID, and B's different contact overwrites it. If the ID is absent in B's validated complete history, `reconcileRemoteDeletionStep:3320–3340` instead marks the restored clean A contact deleted. Dirty records receive existing conflict protections; that does not protect clean restored records from this cross-destination association.

**Offline actual-core proof:** `RestoreProbe.swift` constructs a valid A backup with clean K1BACKUP linked to remote ID 42, preserves the current B database in a recovery package, and uses the actual retained caller's core close/install/reopen sequence while keeping the current settings at `https://destination-b.invalid`, station 2, automaticSync=true. The actual `installDatabase` preserves K1BACKUP's clean linked ID 42. The real `mergeRemote` then receives a local synthetic B record with ID42 and call W9DESTB: the same local contact ID changes from K1BACKUP to W9DESTB, with one row remaining. The generated pre-restore recovery still contains W9BEFORE. There is no network, token, GUI, provider or timer execution in this probe: the UI/timer reachability is established by the current source chain above. Actual core objects are the parent's authorized portable-final objects; the standalone probe compiled/linked in scratch and source hashes/command are retained in `restore-probe-receipt.json`. Build/run exit 0, raw output `restore-probe-run.log` / `restore-probe-driver.log`.

**Existing safeguard comparison and severity:** The modern worker restore deliberately prevents this exact authority confusion: `LiveLogbookMethods.swift:1477–1485` rejects keep-settings restore when the backup URL or station ID differs, before replacement; edit-generation rotation also revokes modern automatic-sync consent. Those safeguards are absent from retained AppModel. High is proposed because an ordinary automatic sync can overwrite or tombstone the operator's restored contacts against the wrong remote authority without an appropriate migration choice. Both the selected A backup and pre-restore recovery package remain available; permanent unrecoverable loss and actual provider writes are not asserted.

**Origin and test gap:** This is preexisting retained AppModel orchestration, unchanged by the reviewed ADIF repairs. It was found in the newly requested partial-path follow-up. `AutomaticSyncTests:97–123` verifies the equivalent modern guard, but does not exercise the retained AppModel restore route. Add a caller-level data-only restore from A while B is retained, with clean overlapping and absent remote IDs; require either a pre-replacement rejection or a reviewed explicit migration/detachment contract, plus automatic-sync consent retirement.

### Follow-up rejected leads / safeguards

- Modern worker restore first stops remote backup and retires PythonContestLane's in-memory child (`LiveWorker.swift:603–604`, `PythonContestLane.swift:253–265`); live contest handles do not keep writing into replaced stores through that supported route.
- Modern restore is serialized under the service NSRecursiveLock, blocks an active manual sync lease, creates a recovery backup, rotates edit generation, writes `.restore-incomplete`, closes its database, records every successful component replacement, rolls back in reverse order on a later failure, and leaves the marker when recovery itself fails (`LiveLogbookMethods.swift:1444–1583,1755–1795`). `RestoreAtomicityTests.swift:10–94` source covers Python/reference/completion failures and failed rollback/reopen refusal; no fresh broad tests repeated.
- Workspace creation uses no-overwrite staged publication and separate identity/defaults; native copies start local-only, without copying credentials (`LiveLogbookMethods.swift:586–626`, `IntegrationWorkspace.swift:89–173`). No concrete authority bypass found there.
- Envelope validation captures sealed bytes, bounds decoded payloads, rejects path traversal/links/case-normalization collisions, validates database checksum/counts and trusted remote package identity before materialization (`BackupEnvelope.swift:32–153`, `BackupManager.swift:259–304,450–534`). Staged database bytes are hash checked again before publication; corrupt bytes fail without replacing the live database.
- Actual sync reconciliation uses bounded BEGIN IMMEDIATE steps, preserves dirty local edits as conflicts, serializes its owning run token, validates cancellation/workspace before writes/acks, and preserves newer foreground edits/deletes in `acknowledgeSynced` (`LogbookDatabase.swift:3069–3097,3155–3395`, `SyncEngine.swift:309–568`). Complete remote history requires metadata/ID coverage and an unchanged first page before deletion; ambiguous identity groups remain held. No additional confirmed sync-core defect in this bounded pass.
